## 1. 证据原则

- 先记录可见事实，再解释含义。
- 页面原文和对象状态优先于文件名、分析者注释和历史总结。
- “没看到”只能证明当前来源未覆盖，不能证明产品没有该能力。
- 同一证据可以支持多个结论，但每个结论都要独立引用证据。
- 同一结论可以引用多个证据；不能把多条弱线索合并后标成页面事实。
- 证据等级描述来源性质，置信度描述判断把握，两者不能互相替代。

## 2. 来源清单

来源编号使用 `SRC-001`、`SRC-002`。推荐字段：

| 字段 | 说明 |
|---|---|
| source_id | 稳定编号 |
| type | screenshot、video、page、log、export、official_doc、prior_report |
| path_or_url | 文件路径或官方链接 |
| captured_at | 页面采集时间；未知时留空 |
| product_version | 可见版本；未知时留空 |
| dimensions_or_duration | 截图尺寸或录屏时长 |
| chronology_status | verified、candidate、unverified |
| access_mode | offline、live_readonly、authorized_test、secondary |
| limitation | 裁切、模糊、缺时间戳、页面未加载等 |
| hash | 可选，用于去重和版本确认 |

文件名和文件夹名只是定位索引。文件名描述与画面冲突时，记录冲突并以画面为证据。

## 3. 证据、结论与冲突

### 证据记录

证据编号使用 `EV-<阶段>-<三位序号>`，例如 `EV-J-001`。

| 字段 | 必填内容 |
|---|---|
| evidence_id | 稳定编号 |
| source_id | 对应来源编号 |
| time_position | 已验证顺序或候选顺序 |
| surface | chat、form、canvas、task、asset、history、preview、error、billing、permission 等 |
| actor | 用户、界面、具名 Agent、自动化、运行时 |
| exact_text_or_object | 最短必要原文或可见对象 |
| action | 点击、输入、选择、生成、出现、消失、失败等 |
| state_before / state_after | 能确认时填写 |
| execution_level | 计划、声称、运行结果、对象结果、下游消费 |
| limitation | 证据限制 |

### 结论记录

结论编号使用 `CL-<阶段>-<三位序号>`。

| 字段 | 说明 |
|---|---|
| claim_id | 稳定编号 |
| claim | 单一、可检验的判断 |
| class | FACT、INFERENCE、DESIGN、UNKNOWN |
| evidence_refs | 一条或多条证据编号 |
| counter_evidence | 反证或冲突编号 |
| confidence | 高、中、低；不能改变 class |
| downstream_artifacts | 使用该结论的报告、图或 Prompt 规则 |
| validation_needed | 继续确认所需页面或操作 |

### 冲突记录

冲突编号使用 `CF-001`。不要在冲突表中选赢家。

| 字段 | 说明 |
|---|---|
| conflict_id | 稳定编号 |
| subject | 同一任务、对象、资产、余额或状态 |
| observations | 各页面或时间的证据编号及可见值 |
| time_alignment | 是否为同一时间快照 |
| impact | 对旅程、完成判断、Agent 契约或架构的影响 |
| current_resolution | unresolved、time_explained、verified_source |
| next_check | 只读条件下可做的下一步 |

## 4. 时间线

1. 从最早可见用户动作或系统入口开始。
2. 优先使用页面消息顺序、明确时间戳、阶段变化和对象版本。
3. 文件名顺序只能作为候选顺序。
4. 同一事件的不同缩放或不同面板截图不得重复计数。
5. 画面同时包含早期聊天和后期对象时，分别记录“聊天事件时间”和“截图采集时间”。
6. 顺序无法确定时保留多种可能，不填造过渡步骤。

## 5. 执行证明

| 等级 | 可观察内容 | 能确认什么 |
|---|---|---|
| L1 计划 | Agent 说“将调用/准备生成” | 只确认计划 |
| L2 自述 | Agent 说“已调用/已完成” | 只确认产品做出该表述 |
| L3 运行结果 | 工具卡、任务卡、状态码显示成功或失败 | 确认页面暴露的运行结果 |
| L4 对象结果 | 预期记录、节点、文件、媒体或交易结果实际出现 | 确认界面层结果存在 |
| L5 消费结果 | 下游读取、预览可用、导出成功或用户实际得到结果 | 确认传播或可用性 |

- 官方工具名不可见时使用 `<功能工具>` 或描述性名称，并标注“非官方工具名”。
- 工具返回成功但对象未出现时，分别记录 L3 成功和 L4 未确认。
- 对象存在但历史、任务或上下文为空时，保留状态冲突。

## 6. 状态与对象核对

按产品形态选择并尽量同时核对：

- 对话或通知中的状态；
- 页面主工作区；
- 任务/运行面板；
- 对象、资产或记录库；
- 历史、版本或审计日志；
- 预览、消费、导出或交付结果；
- 错误与阻塞提示；
- 计费、余额、权限和安全结果。

对每个关键对象检查：标识、类型、生产者、版本、当前状态、引用关系、下游消费者、用户确认、错误状态和上游修改后的有效性。

|---|---|---|---|---|---|
| 正常主流程 |  |  |  |  |  |

## 8. 安全与外部资料

- 只读浏览允许导航、滚动、打开已有对象、历史和预览；控件后果不明时不点击。
- 需要提交、付费、发布、删除、覆盖或影响其他用户时必须有明确授权。
- 不检查 Cookie、会话存储、Token、密码和授权头。
- 外部资料只采用产品官方站点、官方帮助、官方定价、官方 API 或公开政策。
- 官方能力声明与当前任务页面行为分开记录，不自动证明该能力在本场景已执行。

## 9. S0 质量门

- [ ] 查看范围、访问模式和快照时间已记录。
- [ ] 关键来源均有稳定编号和限制说明。
- [ ] 最早可见事件与证据终点已确定，或明确标为未知。
- [ ] 证据记录不夹带隐藏实现判断。
- [ ] 结论记录引用了证据或明确标为未知/建议。
- [ ] 文件名与画面、聊天与状态、对象与历史的冲突已单独登记。
- [ ] 计划、自述、运行结果、对象结果和下游消费已分层。
- [ ] 未覆盖分支已进入覆盖矩阵。
- [ ] 没有敏感信息或未授权写操作。
