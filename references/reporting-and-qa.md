## 1. 交付模式

- **参考级完整模式**：默认。一次任务内严格按 01→02→03→04 连续生成四份 HTML；04 最后生成并作为核心总报告。台账和 Mermaid 只是辅助文件。
- **指定阶段模式**：只生成对应的参考级 HTML。
- **快速模式**：仅在用户明确要求时输出 Markdown。

不得因为时间、来源不足或某阶段不适用而把完整模式静默降级成 Markdown。证据不足应保留 HTML 结构，并在相应章节写明未知和补证动作。

## 2. 文件结构

```text
<产品名>-拆解/
├── 00-范围与来源清单.csv
├── evidence/
│   ├── evidence-ledger.csv
│   ├── claim-ledger.csv
│   └── conflict-ledger.csv
├── report-theme.css
├── report-runtime.js
├── 01-<产品>-用户旅程-页面取证版.html
├── 02-<产品>-Agent契约-页面证据版.html
├── 03-<产品>-<Agent>-功能等价SystemPrompt.html
├── 04-<产品>-产品全景架构-证据分层版.html
└── diagrams/
    └── *.mmd
```

完整模式必须创建四份主报告，缺少任意一份都算未完成。指定阶段模式才只创建对应报告。更新已确认产物时增加版本或标记 `stale`，不要静默覆盖。

完整模式使用临时工作目录逐份生成和校验；01 通过后才生成 02，02 通过后才生成 03，03 通过后才生成 04。最终运行 package 校验后再对用户展示，避免把未完成的单份报告误当成交付。

## 3. 统一视觉系统

四个模板共享 [../assets/report-theme.css](../assets/report-theme.css) 与 [../assets/report-runtime.js](../assets/report-runtime.js)。目标是简约、高级、商务、大方，适合长篇研究阅读：

- 页面背景固定使用 `#121212`，主卡片固定使用 `#1E1E1E`，交互与主强调固定使用 `#4299E1`；正文使用高可读浅灰，事实、推断、建议、未知和风险只使用克制的语义辅色。
- 保持充足留白和舒展行高；正文最佳阅读宽度约 70—86 个中文字符，不用超大标题挤压首屏。
- 卡片使用深灰细边框与柔和轻微阴影建立层级，不使用装饰渐变、发光、玻璃拟态或厚重悬浮效果。
- 字号至少五级：首屏结论、页面标题、章节标题、正文、证据/辅助信息。
- 首屏必须有产品名、报告类型、最重要结论、范围/快照/证据终点元数据和证据图例。
- 页面导航固定在顶部并随滚动高亮；导航顺序与 DOM 章节顺序一致。
- 卡片只用于独立语义单元：Agent 契约、情绪、风险、规则和工具。不要把每段文字套卡片。
- 表格使用浅蓝灰粘性表头、克制悬停和容器内横向滚动；数字列使用等宽数字。
- 交互控件至少 44 px，高对比 `focus-visible`，不依赖颜色单独表达状态。
- 320 px 以上正文可读；375、768、1024、1440 px 有明确布局。
- 不使用外部 CDN、网络字体、装饰图、渐变、Emoji、花哨动画或无意义阴影。交互反馈仅使用必要的颜色和可见状态变化。

最终 HTML 可以引用同目录 CSS/JS。用户要求单文件时再内联，不能丢失交互。

## 4. 四类报告组件

| 报告 | 固定章节 | 必需交互 | 关键组件 |
|---|---:|---|---|
| 用户旅程 | 8 | 导航、补充保存/导出/清空 | 证据表、三类三泳道、情绪、三个问题、机会 |
| Agent 契约 | 9 | 搜索、证据筛选、展开/收起 | Agent 清单、十段契约卡、工具/上下文/关系表、流程图 |
| 功能等价 Prompt | 10 | 复制状态图、复制 Prompt | 边界十问、输入/输出/工具、状态机、四类规则、追溯、测试 |
| 产品架构 | 18 | 证据筛选、复制三类图 | 五条流、分层、上下文、知识、模型、选型、ER/时序/全景、风险 |

模板中的 `{{PLACEHOLDER}}` 必须全部替换。若某模块不适用，保留章节并说明原因，不删除固定章节。

## 5. 可追溯性

推荐属性：

```html
<tr data-evidence-id="EV-J-001" data-source-id="SRC-001">...</tr>
<article data-claim-id="CL-A-003" data-claim-class="inference">...</article>
```

页面可显示 `S01 · E03` 等紧凑芯片，但规范编号必须留在属性、台账或详情中。报告中的所有规范引用必须能回到台账或来源清单。修订证据后检查下游引用，不保留悬空编号。

## 6. 自动与视觉校验

### 自动校验

```bash
python3 scripts/validate_teardown.py <报告> --mode journey
python3 scripts/validate_teardown.py <报告> --mode agent-contract
python3 scripts/validate_teardown.py <报告> --mode functional-prompt
python3 scripts/validate_teardown.py <报告> --mode architecture
python3 scripts/validate_teardown.py <完整交付目录> --mode package
```

有台账时追加 `--ledger` 与 `--manifest`。模板本身使用 `--template`。只有快速 Markdown 使用 `--allow-markdown`。

单份校验必须检查：报告 profile、固定章节及顺序、模板残留、证据标签、专属组件、按钮/筛选、图表源码或不适用理由、契约十段、Prompt 十五个编号段落和测试数量。package 校验必须确认 01—04 各有且仅有一份、文件名前缀与 profile 对应、04 标记为核心总报告。不能只检查关键词。

### 视觉与交互检查

在浏览器以 375、768、1440 px 检查：

- 首屏能否在三秒内看懂报告结论和证据边界；
- 页面级横向溢出、文字截断、重叠和空白；
- 表格、图表只在自身容器滚动；
- 导航锚点、搜索、筛选、展开/收起、复制和补充区可用；
- 所有按钮有 hover、active、focus-visible 和失败反馈；
- 未加载外部资源，关闭网络后仍可阅读和交互；
- HTML 源码章节顺序与视觉顺序相同。

自动校验通过不等于视觉验收通过。两者都完成后才能交付。

## 7. 最终回复

用简短中文说明：生成或更新了什么、辅助台账/图表、校验结果、最重要证据限制、是否修改了目标产品。完整模式必须按 01、02、03、04 顺序列出四个 HTML 链接，04 最后列出并标注“核心总报告”。不要在聊天中再次粘贴整份报告。
